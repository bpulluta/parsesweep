Configuration Reference¶

A ParseSweep run is driven by a single YAML config. Each command reads only its own section, so a config can contain any subset of extraction, compilation, discovery, and validation.

Start small, add as you need¶

Only two keys are required to extract — schema and input_dir:

extraction:
  schema: schemas/personal/my_schema.json
  input_dir: documents/my_domain

Everything else has a default (see the table below). Add a key only when you have a reason to change its default — the Tuning & Iteration guide tells you which key to reach for and when.

These are the values that apply when you omit a key. They come from single source-of-truth constants in the code, so --help and runtime never drift.

Advanced: column-flattening overrides¶

When compiling nested records into flat spreadsheet columns, ParseSweep uses a set of heuristic field-name defaults (which fields name a type, hold a value, carry a unit, and so on). These ship tuned for tabular/rate-style data; if your domain names fields differently, override them per-schema in the schema’s $metadata.compilation.flattening block (e.g. type_fields, value_fields, unit_fields, skip_fields) — no code changes needed. Every knob falls back to the built-in default when omitted.

Annotated template¶

Copy the annotated template below to config/<your_domain>/run.yaml and edit the sections you need. It documents every knob inline.

config/TEMPLATE.yaml¶
# Domain Config Template
# Copy this file to config/<your_domain>/run.yaml
# Usage: psweep run --config config/<your_domain>/run.yaml
#
# Each section is independent — include only what you need:
#   - extraction: required for the extract command
#   - compilation: required for the compile command
#   - discovery: only if you need web document discovery
#   - validation: only if you use multi-model QA/QC validation

domain: your_domain_name

# ─── MODELS (recommended) ─────────────────────────────────────────────────────
# User-defined alias map: keys are alias names (any string), values are
# concrete deployment/model names. Stages reference aliases via their `model:`
# key; if no alias matches, the value is used as-is as the model name.
# When omitted, all stages fall back to the model in your .env (AZURE_OPENAI_MODEL).
#
# Stage model-tier safety: PIN every stage's `model:` to an alias explicitly.
# Leaving a stage unset lets it silently fall back to the .env default —
# a hidden cost/accuracy risk whenever the env or alias map changes.
# Define as many aliases as you need; names are entirely up to you.
models:
  primary: your-model-name           # alias → concrete deployment name
  secondary: another-model-name      # add more aliases as needed

# ─── EXTRACTION ──────────────────────────────────────────────────────────────
extraction:
  schema: schemas/personal/your_schema.json
  input_dir: documents/your_domain        # source documents folder
  output_dir: extracted/your_domain
  model: primary                          # PIN the tier — don't rely on .env default
  # Skip/refresh hygiene: extract skips files with existing output JSON by
  # default (skip_existing=true). Re-run cheaply after config tweaks with no
  # flag; only pass --fresh after changing schema, model tier, or pages.
  # max_context: 600000                   # chars per document (default: 600000)
  # pages:                                 # how to select pages from large PDFs
  #   csv: config/your_domain/page_ranges.csv  # manual ranges per file (wins)
  #   auto_locate:                         # LLM fallback for uncovered large docs
  #     model: secondary                   # pin to an alias — avoid silent .env fallback
  #     section_description: "the section containing your target data"
  #     trigger_chars: 200000              # default: 200000 — only targets docs larger than this.
  #                                        # Set == max_context for zero-regression
  #                                        # targeting (only docs that would be
  #                                        # truncated get page-targeted).
  #     max_selected_pages: 30             # default: 30
  #     keywords: [term1, term2]           # heuristic pre-filter; trims LLM candidates
  #     save_discovered: true              # write discovered_page_ranges.csv for review

# ─── COMPILATION ─────────────────────────────────────────────────────────────
compilation:
  schema: schemas/personal/your_schema.json
  input_dir: extracted/your_domain        # matches extraction output_dir
  output_dir: compiled/your_domain
  # dry_run: false                        # default: false — preview dedup/merges without writing output
  # fail_on_suspicious: false             # default: false — fail compile when suspicious dedup groups found
  # Dedup identity is schema-owned at $metadata.identity.deduplication.
  # Keep uniqueness fields in the schema so every workflow (extract/compile/api)
  # uses the same record identity contract.
  output:
    default_format: excel                 # excel, csv, or both
    # column_order: [field1, field2, ...]  # custom column ordering
    # column_renames: {OldName: new_name}  # rename output columns
    # exclude_fields: [internal_field]     # hide columns from output
    # freeze_columns: 2                   # freeze first N columns in Excel
    # auto_width: true                    # auto-size Excel columns
  # normalization:
  #   state_column: State                # auto-abbreviate US state names
  #
  # synthesis:                           # multi-source reconciliation
  #   enabled: true                      # reconcile many docs → one row per entity
  #   min_sources_for_llm: 2             # skip LLM when only 1 source (cheaper)
  #   group_by: ["entity.key_field"]     # one output row per distinct value
  #   identity_fields:                   # context fields (first non-empty wins)
  #     - entity.category
  #   citation_field: source.url         # becomes citation list in output
  #   reconcile_fields:
  #     - {field: some_field}
  #     - {field: dated_field, evidence: evidence_field}

# ─── DISCOVERY (optional) ────────────────────────────────────────────────────
# discovery:
#   targets_csv: targets.csv
#   queries:
#     - "{entity_name} {state} filetype:pdf"
#   search:
#     provider: serpapi
#     max_results: 10
#   selection:
#     max_per_target: 3
#     exclude: [news, blog, press release]
#   browser_mode: false                   # default: false — set true to download via headless Chrome (bot-protected sites)
#   partition_by: [state, jurisdiction]   # output layout by_<field>/<value>/… from target metadata
#   document_review:
#     model: secondary                    # pin to an alias — avoid silent .env fallback
#     document_description: "the authoritative source document"
#     keep_top: 1
#     action: move

# ─── QA/QC (optional) ────────────────────────────────────────────────────────
# Run two models on the same documents and compare their outputs field-by-field.
# Uncomment the block below to enable. Keep this minimal.
#
# validation:
#   models: [primary, secondary]      # Two model tiers to contrast.
#   output_dir: validated/your_domain
#   report:
#     include_csv: false
#     include_missing_in_queue: true
#     include_low_signal_presence_in_queue: false  # keep obligation-only one-sided rows out of reviewer queue
#     identity_columns: compact                     # compact | expanded
#     include_value_unit_column: true
#     evidence_detail: full                        # full | compact | off
#     evidence_max_chars: 200
#   comparison_approach: mixed            # mixed | numeric_only | text_review
#   record_matching:
#     key_fields: [feature, applies_to, specific_subject]
#     fuzzy_key_fields: [applies_to, specific_subject]
#     semantic_match_threshold: 0.38
#   comparison:
#     primary_fields: [value, units, value_interpretation, obligation]
#     collapse_percent_context: false   # true = treat "percent above/below ..." as "percent"
#     unit_equivalence_groups:          # optional unit synonym groups
#       - [feet, ft]
#       - [hours, hrs, hr]
#       - [decibels, dB, dBA, dB(A)]
#   judge:                                # Optional but recommended for mixed/text_review.
#     enabled: true
#     model: judge
#     apply_on: all                       # none | non_numeric | all
#     row_equivalence: true
#     pair_unmatched: true
#     min_confidence: high
#     strictness: "If uncertain, mark non-equivalent."
