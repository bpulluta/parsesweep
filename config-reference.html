Configuration Reference¶

This page is the single reference for run.yaml. Every key, default and rule below is taken from the loaders that enforce them; the Command Reference renders every CLI option from the live command definitions.

The run config¶

A domain lives in config/<domain>/:

config/<domain>/
├── run.yaml       # this file: runtime behavior for every stage
├── schema.json    # extraction contract (see Schema Authoring)
├── targets.csv    # optional roster: one row per target
└── samples/       # optional human reference sheets for validation

Only the config passed with --config is loaded. Each command runs its own section and validates all supplied sections. Loading is strict at every level: unknown keys fail with a did-you-mean suggestion naming the file and key path; quoted booleans ("false"), invalid regexes, non-http(s) URLs and out-of-range limits fail before any work starts. Relative targets, pages.csv and validation.references paths resolve against the config directory. Credentials never go in YAML; set them in the environment or .env (see Environment variables).

Check a config without network calls or run artifacts:

pixi run psweep run --config config/<domain>/run.yaml --validate-config
pixi run psweep discover --config config/<domain>/run.yaml --show-effective-config

config/TEMPLATE.yaml is a valid starting point covering all four stages:

config/TEMPLATE.yaml¶
# Copy to config/<domain>/run.yaml beside schema.json and targets.csv.
# Every key, default and rule: docs/config-reference.md. Keys go in .env.
domain: my_domain
models:                               # aliases used by every stage
  primary: gpt-4o
  secondary: gpt-4o-mini
discovery:
  targets: targets.csv                # columns fill {placeholders}
  queries:
    - '"{name}" {state} installation manual filetype:pdf'
  partition_by: [state, name]         # curated/by_state/<s>/by_name/<n>/
  selection:
    max_per_target: 2
extraction:
  model: primary
compilation:
  output:
    default_format: csv               # csv | excel | both
validation:
  models: [secondary]                 # contender; add references: [labels.csv]

config/example/ is the smallest runnable domain: three targets with known urls, so it needs no search key. Getting Started runs it.

Discovery¶

Discovery finds, downloads and curates documents. It needs no schema and no LLM credentials unless document_review is configured; search needs SERPAPI_API_KEY.

Inputs¶

Key

Meaning

targets

.csv/.json path, inline list of rows, or {cross_product: {dimensions: [...]}}.

sources

Shared http(s) URLs downloaded for every run and always kept (saved under _shared/).

queries

Search templates: {field} is required, {field?} optional. Search runs only when queries or a target query is set.

partition_by

Target fields that lay out curated output as by_<f1>/<v1>/by_<f2>/<v2>/. Without it a target’s files go under _targets/<id>/.

Each target row is one target. Every column except urls and query is metadata: it fills query templates, partitions output and is recorded as provenance. urls lists the target’s own documents or pages (a list, or a|b in a CSV cell) and is always downloaded and kept; query replaces queries for that row. Discovery never infers geography from query text. CSV headers may carry a UTF-8 BOM.

A target’s identity is its partition_by values (every metadata column when partition_by is unset). Identity names the target in checkpoints, review prompts and curated ownership, so it must be unique: duplicate rows fail with both row locations. --target-limit/-n N runs only the first N targets.

discovery:
  targets:
    - {jurisdiction: Chaffee County, state: CO,
       urls: [https://www.chaffeecounty.org/land_use_code.pdf]}
    - {manufacturer: Generac, query: "Generac 250kW generator manual pdf"}
  # or: targets: targets.csv
  # or: targets: {cross_product: {dimensions: [
  #       {name: state, values: [CO, NM]},
  #       {name: county, dataset: counties.csv, column: county}]}}
  queries:
    - "{jurisdiction} {state} geothermal ordinance pdf"

link_prioritization key

Default

Meaning

mode

heuristic

heuristic ranks candidates before download; off disables ranking.

top_k

0 (no cap)

Optional global ranking cap.

keywords

document, download, guide, report

Terms that raise a candidate’s score; replace the fallback.

domain_scores

—

Domain → score adjustment ({"municode.com": 0.2, ".gov": 0.15}). A hostname matches itself and its subdomains; a leading-dot suffix matches every host ending in it; negative scores demote.

shopping_path_keywords

—

URL path terms that lower a candidate’s score.

The heuristic score weighs file type (35%), domain_scores (25%) and keywords (25%); PDFs are preferred to web pages. Ranking is a boost, never a scope: for strict sources combine crawl.allowed_domains with include_url_patterns. Positive hostname entries (not .gov-style suffixes) also name the code hosts for the two post-review retries of targets left without a curated document: a SerpApi site: search under the code-host path already found, and a browser crawl of JavaScript-shell code-host pages. Both run only with document_review and document_classifier.nice_to_have_keywords; the browser crawl also needs a browser (crawl.browser_escalation or crawl.browser_downloads).

document_review¶

Optional, paid LLM curation; it runs only when document_description is set.

Key

Default

Meaning

document_description

—

What a correct document is; may use {field} target templates.

model

default model

models: alias or model name.

keep_top

1

Primary documents kept per target.

max_chars

12000

Text sent per document.

keywords

classifier keywords

Terms used to pick the excerpt sent for review.

deduplicate_redundant

true

Drop redundant copies before keeping the top ones.

deduplication.key_fields

—

Fields that identify redundant copies (e.g. [path_basename, review_doc_kind]).

The reviewer grades each document 0–4 against an anchored rubric. In review.csv, relevance = grade / 4 and llm_is_primary = grade ≥ 3; selection keeps the top keep_top non-redundant primaries per target, ranked by relevance. Grades are cached by content and grading inputs in discovered/.review_cache/ and reused across runs. Recordings are graded on their transcript: a run’s copy inherits the curated copy’s transcript (matched by SHA-256) before review. A recording not yet transcribed (first run) is kept without review and transcribed at extraction. Edit human_decision (keep/reject) in review.csv and run psweep curate --config … to republish the curated selection; the next psweep extract withdraws the records of documents it dropped.

policy and retention¶

Key

Default

Meaning

policy.robots_mode

warn

ignore, warn or enforce robots.txt (matched on the ParseSweep token).

policy.tos_mode

warn

ignore, warn or enforce terms-of-service checks.

policy.acknowledged_tos_domains

—

Hosts whose terms you have reviewed.

retention.documents

all

all keeps every download; curated deletes the run’s non-curated downloads; none also deletes the run’s documents and curated copy (rejected by run when extraction follows).

curated and none keep the files and text caches of incomplete targets and sources, which the next run resumes from, and remove superseded run files once the checkpoint is written. Fully reused runs delete nothing.

Strict robots/ToS enforcement covers HTTP acquisition only and fails before any browser navigation. The default User-Agent is Mozilla/5.0 (compatible; ParseSweep/<version>).

Page selection¶

extraction:
  pages:
    csv: page_ranges.csv          # file_path,start_page,end_page (1-based, inclusive)
    auto_locate:                  # LLM fallback for documents the CSV does not cover
      section_description: "the residential rate schedules"
      trigger_chars: 200000       # default; only larger documents are targeted
      max_selected_pages: 30      # default; total, referenced pages included
      keywords: [rate schedule]   # optional cheap pre-filter
      model: secondary            # optional locator model
      save_discovered: true       # write found ranges for review

pages accepts only csv, auto_locate and range, and auto_locate only the keys shown plus enabled; anything else fails validation. pages.csv resolves against the config folder (the --pages-csv CLI flag against the working directory). A row’s file_path matches a document by path, by path relative to the input folder, or by file name; give a file one row per range. CSV rows win; leave both pages empty to force the full document. pages.range (or --pages 27,68-73) selects pages for a single file: comma-separated pages and inclusive ranges.

auto_locate shows the locator model the opening lines of every page and asks for the pages of the described section. It then reads those pages in full and adds the parts they refer to elsewhere in the document, such as “charges specified in Tariff Sheet 75” or “riders on Sheet 80”, and repeats with the added pages until nothing new is referenced. max_selected_pages caps the total. Relevant pages it leaves out are logged as a warning and recorded in the record’s coverage.omitted_page_ranges. The extracted text marks each skipped stretch with [Omitted pages: 28-67].

Selections are cached in .pages/ beside the document. If the section cannot be located, the full document is extracted. If a reference pass fails, the pages found so far are used and the document is located again on the next run. With save_discovered, extracted/discovered_page_ranges.csv (the pages.csv columns, one row per range) lists the pages behind every current record, reused records included.

LLM calls¶

Every transient provider failure — HTTP 408, 429 and 5xx, timeouts and dropped connections — is retried up to 4 attempts in total with exponential backoff (2 s, capped at 30 s). TLS failures and other 4xx errors are terminal. Each retry logs a warning with the model, the failure category and the attempt, prefixed with the document being processed; provider error text is never logged.

Roster-anchored extraction¶

When the schema’s identity.deduplication.key_fields equal discovery.partition_by, extraction runs in roster mode: entity names in the text are matched exactly (after normalization) against the roster’s last partition_by field. A name shared by targets in different states is assigned by state evidence near the match, falling back to the whole document: addresses (, AZ or AZ 85001), full state names, state-labelled table cells (State: CA), or a state code alone on the line after a line that is exactly a roster name. Without evidence every candidate is kept. Names unique to one target are never dropped. Partial overlap between key_fields and partition_by is an error.

Audio¶

Recordings (.mp3 .m4a .wav .ogg .flac) are documents. Set extraction.transcription_model to a models: alias of a transcription model. ffmpeg (installed by pixi) transcodes each recording to mono 16 kHz MP3 and splits it into ~5-minute chunks cut at the quietest point; chunks are transcribed in parallel and each starts with an exact [hh:mm:ss] offset. Measured cost is about $0.22 per audio hour. Transcripts are cached beside the recording in .text/<filename>.txt (with .meta.json), like OCR text, so each file is transcribed once.

Headers are the schema field’s title (or its name); unknown headers fail. Row shape ($metadata.compilation.flattening) and deduplication keys belong in the schema — see Schema Authoring.

Roster mode. When discovery declares targets and partition_by, compile emits one row per target in roster order. Agreeing values win; conflicts prefer target-scoped sources, then the value backed by most sources; missing values (null, blank, or an empty list or object) are NA. A list of primitives becomes one comma-joined cell; other lists and objects become compact JSON. Extra target columns pass through, plus sources, confidence (high ≥ 2 agreeing sources, medium, low on conflict, none) and evidence ({field: {value, url}}, adding the quote of each evidence field and conflict: true when sources disagree).

Excel batches above 1,048,575 rows or with cells over 32,767 characters fail before export; use CSV for large outputs.

Validation¶

validate scores the primary table (from extraction.model) against contender models and human reference sheets. run adds it when a validation: block exists.

Key

Meaning

models

Contender models: aliases, extracted and compiled into validated/<alias>/; must differ from extraction.model and each other.

references

0..N human CSV sheets (config-relative) whose headers are compiled titles; labelled by file stem.

judge

models: alias that rules on disputed cells only; omit to skip judging.

fields

Scored subset (default: every scorable field).

min_accuracy

Gate in (0, 1]: exit 1 when the primary falls below it against any reference. Needs references.

key_fields, quote_field

Rows mode (no roster) only: row identity (required there) and each row’s verbatim quote.

At least one of models or references is required. Cells where every contender agrees are not judged; the judge sees only disagreements, checking each candidate against its quote. Misses are labelled no_docs (no curated document) or extraction. Accuracy carries a 95% Wilson interval. validate --sample N [--seed S] writes a blank, seeded labelling sheet with no LLM calls. Outputs in outputs/<domain>/validated/: cells.csv, summary.csv, summary.json.

Document types and limits¶

Supported inputs (discovery downloads exactly these; extraction reads them):

Kind

Extensions

Read as

Documents

.pdf .doc .docx .txt

Text, with OCR for scanned PDFs

Web pages

.html .htm

Main text

Data

.csv .xlsx .json

One Header: value | … line per record (CSV, each sheet, JSON record arrays such as Socrata/ArcGIS/GeoJSON/CKAN); other JSON as indented text

Audio

.mp3 .m4a .wav .ogg .flac

Transcript (Audio)

URL eligibility (selection.require_supported_document): a URL with a supported extension, no extension, or a suffix unknown to Python’s MIME table (.php, .aspx, .cfm, …) is eligible — the response MIME type decides what it is. A suffix of a known unsupported type or encoding (.jpg, .zip, .gz) is rejected before download.

Byte limits. Files streamed to disk stop at 1 GiB decoded (PSWEEP_MAX_RESPONSE_BYTES overrides it) and abort after runtime.timeout_seconds without data. Pages, search and API responses read into memory stop at 50 MiB and must finish within the timeout. An oversized response is a failed download (partial_failure), never retried; raise the limit and rediscover with --fresh.

Runs, reuse and exit codes¶

Status

Exit

Meaning

success, reused, dry_run

0

Done, verified reuse, or a valid plan.

failed

1

The stage failed.

empty

2

Nothing usable and no failure.

partial_failure

3

Usable output plus recorded errors.

run stops at 1 or 2, continues past 3, and exits 3 at the end when any stage was partial. Exit codes do not depend on -q/-v.

Discovery resume. The checkpoint (discovered/checkpoint.json) records each target and shared source separately, keyed by the effective config fingerprint and SHA-256 evidence of its files. Adding a target fetches only that target; changing a target’s urls or rendered queries re-runs it.

  • A complete item makes no requests on the next run.

  • An item left incomplete — transient failure, unfinished crawl or search, max_pages or max_files reached — publishes what it has additively, and the next run re-fetches the listing, reuses every earlier download whose SHA-256 still matches (no request, no max_files slot), skips terminal outcomes (e.g. 404) and fetches only the rest. A capped listing converges batch by batch.

  • Transient failures (timeouts, connection errors, truncated streams, HTTP 408/429/5xx) are retried in the run and leave the item incomplete. Bot challenges (429/5xx with cf-mitigated, x-vercel-mitigated or x-amzn-waf-action) are retried in the run but are final across runs. TLS errors and other 4xx responses are terminal.

  • discover --fresh ignores the checkpoint and search cache, re-checks completed listings (new children of a completed listing need it), and replaces the curated partitions of the targets it processes.

Extraction reuse. A record is reused only when source, schema, resolved model and settings, and record bytes still match; otherwise it is re-extracted. Reuse needs no credentials. A record whose source document no longer exists under the input folder is withdrawn: extract deletes it, names it in the summary and lists it under withdrawn in the run manifest, so compile drops its rows. Records from other input folders are left alone, and validate reports a primary with records to withdraw as stale. extract --fresh resets the output after a successful preflight. compile --fresh clears stale compiled files; validate --fresh clears validated/. run --fresh passes --fresh to every stage.

Caches. OCR text and transcripts: .text/<filename>.txt + .meta.json beside the document, verified by size, mtime and SHA-256 and carried to a re-downloaded file with the same SHA-256. Page/section targeting: .pages/, .sections/. Review grades: discovered/.review_cache/. Delete a cache directory to force that work again.

Outputs¶

outputs/<domain>/
├── discovered/
│   ├── checkpoint.json
│   ├── curated/                 # consolidated input to extraction
│   └── runs/<run_id>/           # manifest.json, download_index.csv, review.csv,
│                                # documents/, curated/ (latest -> newest run)
├── extracted/                   # one JSON record per document + manifests
├── compiled/                    # <domain>.csv/.xlsx, run_accounting.json
└── validated/                   # cells.csv, summary.csv, summary.json, <alias>/
