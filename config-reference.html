Configuration Reference¶

This page is the single reference for run.yaml. Every key, default and rule below is taken from the loaders that enforce them; the Command Reference renders every CLI option from the live command definitions.

The run config¶

A domain lives in config/<domain>/:

config/<domain>/
├── run.yaml       # this file: runtime behavior for every stage
├── schema.json    # extraction contract (see Schema Authoring)
├── targets.csv    # optional roster: one row per target
└── samples/       # optional human reference sheets for validation

Only the config passed with --config is loaded. Each command runs its own section and validates all supplied sections. Loading is strict at every level: unknown keys fail with a did-you-mean suggestion naming the file and key path; quoted booleans ("false"), invalid regexes, non-http(s) URLs and out-of-range limits fail before any work starts. Relative targets, pages.csv and validation.references paths resolve against the config directory. Credentials never go in YAML; set them in the environment or .env (see Environment variables).

Check a config without network calls or run artifacts:

pixi run psweep run --config config/<domain>/run.yaml --validate-config
pixi run psweep discover --config config/<domain>/run.yaml --show-effective-config

--show-effective-config lists every setting with its source: (config) or (cli) for values you set, and (default) for the built-in value a run will use (none means unset; for max_files, max_review_calls and max_search_calls that means unbounded). psweep config --show-runtime-catalog tags each key required, optional or advanced; discovery.targets or discovery.sources must be present, which preflight enforces.

config/TEMPLATE.yaml is the search and review starter. Its uncommented values are required keys or deliberate recommendations, and the commented blocks are optional features:

config/TEMPLATE.yaml¶
# Search + review starter. Copy to config/<domain>/run.yaml beside schema.json and targets.csv.
# Required: discovery.targets (or sources) and, for search, queries. Every other key
# has a built-in default (docs/config-reference.md). API keys never go in YAML; set them in .env.
domain: my_domain
models:                               # one cheap and one strong model from your provider
  primary: gpt-4o
  secondary: gpt-4o-mini
discovery:
  targets: targets.csv                # columns fill {placeholders}
  queries:
    - '"{name}" {state} installation manual filetype:pdf'
  partition_by: [state, name]         # curated/by_state/<s>/by_name/<n>/
  search:
    params: {udm: web}                # Google "Web" tab: honours quotes and filetype:
    # fallback_queries: ['"{name}" {state} manufacturer manual']  # only for targets still short; needs document_description
  selection:
    max_per_target: 4                 # downloads graded per target (>= keep_top); one cheap review call each
  document_review:                    # cheap grading keeps irrelevant downloads out of paid extraction
    document_description: "Installation manual for {name} in {state}."
    model: secondary
    keep_top: 2                       # documents extracted per target (<= max_per_target): the main cost driver
    # escalate_model: primary         # stronger model only for ambiguous or failed grades
  # runtime:                          # attempt ceilings once you scale
  #   max_search_calls: 200           # about targets x queries
  #   max_review_calls: 12            # about 3 x max_per_target
extraction:
  model: primary
  # pages:                            # large PDFs: send only the relevant pages
  #   auto_locate:
  #     section_description: "the installation instructions"
  #     model: secondary              # must differ from extraction.model
compilation:
  output:
    default_format: csv               # csv scales; both adds .xlsx (built-in default)
# validation:                         # when converging: measure accuracy
#   references: [samples/labels.csv]  # hand-labelled targets; headers are compiled titles
#   min_accuracy: 0.85
#   models: [secondary]               # also compare a cheaper model (re-extracts every document)

config/example/ is the smallest runnable domain: three targets with known urls, so it needs no search key. Getting Started runs it.

Discovery¶

Discovery finds, downloads and curates documents. It needs no schema and no LLM credentials unless document_review is configured; search needs SERPAPI_API_KEY.

Inputs¶

Key

Meaning

targets

.csv/.json path, inline list of rows, or {cross_product: {dimensions: [...]}}.

sources

Shared http(s) URLs saved under _shared/; bypass relevance selection, but obey explicitly enabled PDF screening.

queries

Search templates: {field} is required, {field?} optional. Search runs only when queries or a target query is set.

partition_by

Target fields that lay out curated output as by_<f1>/<v1>/by_<f2>/<v2>/. Without it a target’s files go under _targets/<id>/.

Each target row is one target. Every column except urls and query is metadata: it fills query templates, partitions output and is recorded as provenance. urls lists the target’s own documents or pages (a list, or a|b in a CSV cell) and bypasses relevance selection, but obeys explicitly enabled PDF screening; query replaces queries for that row. Discovery never infers geography from query text. CSV headers may carry a UTF-8 BOM.

A target’s identity is its partition_by values (every metadata column when partition_by is unset). Identity names the target in checkpoints, review prompts and curated ownership, so it must be unique: duplicate rows fail with both row locations. --target-limit/-n N runs only the first N targets.

discovery:
  targets:
    - {jurisdiction: Chaffee County, state: CO,
       urls: [https://www.chaffeecounty.org/land_use_code.pdf]}
    - {manufacturer: Generac, query: "Generac 250kW generator manual pdf"}
  # or: targets: targets.csv
  # or: targets: {cross_product: {dimensions: [
  #       {name: state, values: [CO, NM]},
  #       {name: county, dataset: counties.csv, column: county}]}}
  queries:
    - "{jurisdiction} {state} geothermal ordinance pdf"

link_prioritization key

Default

Meaning

mode

heuristic

heuristic ranks candidates before download; off disables ranking.

top_k

0 (no cap)

Optional global ranking cap.

keywords

document, download, guide, report

Terms that raise a candidate’s score; replace the fallback.

domain_scores

—

Domain → score adjustment ({"municode.com": 0.2, ".gov": 0.15}). A hostname matches itself and its subdomains; a leading-dot suffix matches every host ending in it; negative scores demote.

shopping_path_keywords

—

URL path terms that lower a candidate’s score.

The heuristic score weighs file type (35%), domain_scores (25%) and keywords (25%); PDFs are preferred to web pages. Ranking is a boost, never a scope: for strict sources combine crawl.allowed_domains with include_url_patterns. Positive hostname entries (not .gov-style suffixes) also name the code hosts for the two post-review retries of targets left without a curated document: a SerpApi site: search under the code-host path already found, and a browser crawl of JavaScript-shell code-host pages. Both run only with document_review and document_classifier.nice_to_have_keywords; the browser crawl also needs a browser (crawl.browser_escalation or crawl.browser_downloads).

document_classifier¶

Key

Default

Meaning

required_keywords

—

Terms looked for in the first pages of each download.

nice_to_have_keywords

—

Terms that raise the score; also the default document_review.keywords.

min_required_matches

1

Required terms that must appear.

action

warn

warn records the keyword result; filter rejects failing downloads (never configured URLs).

pdf_screening

"off"

"off" skips PDF revision screening; warn records evidence; hold keeps flagged or incompletely inspected PDFs out of automated curation pending human review. Quote "off" in YAML so it is not parsed as a boolean.

action: warn still sends keyword failures to paid review; filter drops them first. Before switching, compare classification_passed in download_index.csv with the review outcome (review_is_primary).

PDF screening is independent of keyword relevance and applies to configured URLs as well as discovered PDFs. Other formats are unchanged. For example:

discovery:
  document_classifier:
    pdf_screening: hold

The inspector checks all native PDF pages for strikeout annotations and thin strokes/filled rectangles crossing text. Highlights are recorded as weak evidence and do not cause a hold on their own; colored text alone is not a revision signal. It also reuses selection.draft_patterns (when selection.exclude_draft is true) against title/subject/keywords metadata and full-line short headers, not arbitrary body sentences. There is no built-in draft vocabulary. Scanned/image-heavy, password-protected (cannot be opened without a password), undecryptable, corrupt, or otherwise incompletely inspected PDFs are held in hold mode, without OCR/vision calls. PDFs that carry only owner (permission) restrictions open without a password and are inspected normally. Text is never edited to remove crossed-out clauses.

The manifest’s document_eligibility contains versioned, content-hashed evidence, page coverage and limitations. review.csv and download_index.csv summarize eligibility and effective curated_selected. A hold is not a download/provider failure and does not consume a review top-N slot. Set human_decision to keep or reject in the existing ledger and run psweep curate --config …; explicit human decisions override automated screening. Unresolved held originals and text caches are retained even with retention.documents: curated or none so they can be reviewed.

Policy or detector changes invalidate discovery completion reuse. Existing curated files are reconciled on the next discovery run; if partial acquisition would retain an unchecked prior PDF, publication stops rather than silently passing it to extraction. Complete discovery and resolve holds before extracting from that corpus. Direct-path extraction and extraction without rediscovery deliberately bypass this screening; it is not a second extraction filter.

No findings does not mean legally final or currently in force. An adopted amendment can have strikeouts, and a clean-looking proposal can have none. Holds request human verification, not a determination of legal status. Use warn or leave screening off in domains that need proposals and change histories.

document_review¶

Optional, paid LLM curation; it runs only when document_description is set.

Key

Default

Meaning

document_description

—

What a correct document is; rendered separately per target with required {field} and optional {field?} templates. Missing required/malformed tokens fail preflight.

context_fields

identity only

Extra roster metadata columns supplied as scope hints (e.g. organization, address). Names must exist; blank hint values are omitted. Does not change partition_by or target IDs.

model

default model

models: alias or model name.

escalate_model

absent/off

One stronger semantic grading decision for grade-2 ambiguity or failed/malformed initial grading, subject to actual-attempt budgets.

keep_top

1

Primary documents kept per target.

prefer_newest

false

For domains where only the latest edition is valid (e.g. tariffs). Grading also asks for the effective date, and among qualified primaries (grade 3-4) a document whose quoted date provably precedes another’s is never chosen (a year or month spans the whole period). Undated documents are kept and ranked by grade, then provenance; a run note lists them. Each extra keep_top slot takes the next-newest edition, and comparative deduplication keeps the newest of proven-redundant copies. Requires document_description; rejected with coverage. Enabling it changes the grading prompt, so that domain’s documents are graded again once.

coverage

absent/off

Domain-defined label → evidence-description map. Descriptions support target templates. Verified labels guide complementary source selection and trigger fallback for missing coverage. Labels use letters/digits/_/-, starting with a letter.

max_chars

12000

Text sent per document.

keywords

classifier keywords

Terms used to pick the excerpt sent for review.

deduplicate_redundant

true

Drop copies whose review evidence (scope, claim kind, content quote, coverage) is identical. Deterministic; no LLM call.

The reviewer grades each document 0–4 against an anchored rubric. Grades3–4 must satisfy every mandatory requirement in document_description; ‘partial’ means missing optional detail, not missing required evidence. The reason quotes the deciding source content or identifies what is absent. In review.csv, relevance = grade / 4 and llm_is_primary = grade ≥ 3; llm_selected is blank for documents no review graded (use curated_selected for what was published); selection keeps at most keep_top non-redundant primaries per target. Without coverage, grades then reproducible provenance break ties (with prefer_newest, provably older dated editions are excluded first). With coverage, newly covered verified labels take priority, then grade; supported publication dates break ties only for matching scope/claim-kind and compatible date precision. Grades are cached by content and grading inputs in discovered/.review_cache/ and reused across runs. Recordings are graded on their transcript: a run’s copy inherits the curated copy’s transcript (matched by SHA-256) before review. A recording not yet transcribed (first run) is kept without review and transcribed at extraction.

A grade whose quotes are not found contiguously in one excerpt segment is repaired once, then settled. The repair is ONE same-model request that repeats the rejected quote and the failing evidence paths and restates the copy rule; it never supplies or fuzzy-matches text, is not used with escalate_model or after a provider error, and is a metered review attempt (a failing grade costs at most one extra call). If it also fails (with escalate_model: if both routes fail), the document is review_unverifiable: held and not curated, a terminal outcome whose reason shows in review.csv llm_reason. It is stored as a negative entry in discovered/.review_cache/ under the grade’s own key, so the same bytes and grading inputs are never billed again and the partition completes (worst case 2 calls per unique document per grading-input version). Changing a grading input (model, description, prompt, keywords, max_chars) changes the key and retries it; provider, transport and attempt-budget failures stay retryable. human_decision keep/reject resolves a held document.

The record’s review_initial_error reads invalid document grade evidence: ungrounded <path> (contract for a malformed grade). review_initial_failure (review_escalation_failure for the escalation route) holds the kind, failing evidence paths and each rejected quote truncated to 300 characters, and review_initial_repair marks a grade that was repaired; these stay only in the local discovery manifest.

Edit human_decision (keep/reject) in review.csv and run psweep curate --config … to republish the curated selection; the next psweep extract withdraws the records of documents it dropped.

Automatic qualification and bounded recovery¶

Review receives structured target identity plus configured context fields as untrusted hints, never proof of a source fact. Templates change the description per target without changing the data contract. Source text must establish the specific entity/scope. Grades0–1 reject; grades3–4 qualify; grade2 can escalate when escalate_model is configured. Exhausted provider routes are not repeatedly hammered during that run: eligible escalation is used or work remains pending. Successful initial grades are reused when a failed escalation resumes. Document/request-specific rejections do not disable unrelated requests on that route.

With search.fallback_queries, discovery runs at most one extra stage for weak targets below document_review.keep_top distinct qualified sources or missing configured coverage labels, including targets with zero downloads. It does not infer field-level gaps from schema field names. Pending search/download/review failures must finish first; provider outages do not launch search loops. Combined initial/fallback sources are deduplicated by exact content/final URL, globally top-N selected and subject to host diversity. Configured target URLs explicitly bypass relevance review and are not counted as automatically verified evidence.

discovery:
  queries: ['"{name}" "{area?}" technical specification']
  search:
    fallback_queries: ['"{name}" "{area?}" manufacturer installation record']
  document_review:
    document_description: "Direct specification evidence for {name} at {address?}; not a sibling asset."
    context_fields: [organization, address]
    model: secondary
    escalate_model: primary
    keep_top: 3
    coverage:
      specification: "An explicit capacity and unit for {name}."
      applicability: "A direct statement of which variant/site the specification covers."
  selection:
    max_per_target: 8
    max_per_host_per_target: 2
  runtime:
    max_review_calls: 12
    max_search_calls: 200

Limits above are examples, not a recommendation for every domain. Review-call limits apply per target per run; search limits apply across the run. Both count physical requests/retries, including failures with unknown pricing, and cache hits are free. Guard exhaustion sends no request and leaves resumable pending work. These bound attempts, not dollars when provider pricing/usage is unknown.

Adaptive search persists query results even when ordinary search.cache is disabled (reported in notes) so interrupted stages can resume without repaying valid queries. Configured TTL remains honored; expired responses may need a new request. Completed unchanged targets still skip work. Low source coverage after exhausting fallback is reported separately from an interrupted failure. Adaptive dry runs/config checks make no paid calls. Without fallback, discover --dry-run performs live searches (paid unless cached) and downloads nothing; adaptive (fallback_queries) dry runs skip search and review.

Grounded review evidence and bounded selection¶

The existing grading call returns review_evidence: identity/content quotations, quoted scope and claim-kind descriptions, optional quoted source-publication date and precision, and quoted configured coverage labels. Accepted grades3–4 require identity/content and scope/claim evidence that occurs in an actual sampled segment. Quotes cannot bridge disconnected sample windows or borrow target metadata. Matching ignores case, punctuation and spacing on whole words, as in extraction, but review quotes must be contiguous: an ellipsis is literal punctuation (such as a table-of-contents dot leader), never an elision. Invalid/fabricated evidence follows the existing failed-review/escalation path; old grade contracts are invalidated by prompt/schema identity. This verifies text occurrence, not entailment, factual truth or document-wide completeness.

Source dates are calendar-valid ISO values with day/month/year precision, tied to quoted text; unknown dates remain unknown. Download timestamps never substitute for publication dates. Direct/reported statements and scope stay source-specific hints in the extraction record and reconciliation input; they are not automatically promoted to achieved facts or a domain-independent authority ranking.

Review dedup is computed in code from the verified source evidence, with no LLM call. Byte-identical files are dropped first. Then documents whose scope, claim kind and content quote are equal are copies: the one with the broadest coverage (ties: best rank) is kept. A differing scope, claim kind, quote or coverage value keeps both sources, and documents with invalid evidence are never dropped.

Finite runtime.max_files allocates new ordinary fetch opportunities round-robin across owners, retaining their ranking. Configured/reused outcomes stay free; unbounded file acquisition retains its existing order. Fallback queries likewise run by query slot across weak targets before the next slot, preventing early targets from consuming every remaining request. Partial budgets/HTTP/provider failures remain pending; exhausted missing coverage is distinct and reported in compact target summaries. One source can cover multiple labels; labels do not bypass mandatory qualification or automatically exceed keep_top/host limits.

Checkpoint verification memoizes actual hashes only within a load by file identity and stat fingerprint, so shared artifacts are hashed once rather than once per owner. It rejects symlinks, missing/changed files and changes during hashing; there is no persisted stat-only trust across runs. Disk review caches avoid retaining duplicate successful decisions in long-lived memory; direct no-cache reviewer use can still retain decision/failure memos for its instance lifetime.

No manually verified per-location URLs/aliases are required. Domain-specific source preferences, scope and query wording stay in YAML; schema fields and validity rules remain the extraction data contract. Qualification grades and quote presence do not independently establish truth or an accuracy threshold.

Page selection¶

extraction:
  pages:
    csv: page_ranges.csv          # file_path,start_page,end_page (1-based, inclusive)
    auto_locate:                  # LLM fallback for documents the CSV does not cover
      section_description: "the residential rate schedules"
      trigger_chars: 200000       # default; only larger documents are targeted
      max_selected_pages: 30      # default; total, referenced pages included
      keywords: [rate schedule]   # optional cheap pre-filter
      model: secondary            # required when enabled; not the extraction model
      save_discovered: true       # write found ranges for review
      subject_fields: [utility_name, short_name]  # optional; target columns used as identity phrases

pages accepts only csv, auto_locate and range, and auto_locate only the keys shown plus enabled; anything else fails validation. pages.csv resolves against the config folder (the --pages-csv CLI flag against the working directory). A row’s file_path matches a document by path, by path relative to the input folder, or by file name; give a file one row per range. CSV rows win; leave both pages empty to force the full document. pages.range (or --pages 27,68-73) selects pages for a single file: comma-separated pages and inclusive ranges. Setting pages.csv and pages.range together in the config fails at load (the range would be ignored); the --pages flag still yields to a configured CSV.

Scope precedence, highest first: (1) a pages.csv row, or a blank row for the full document; (2) pages.range / --pages, used only when no CSV applies; (3) auto_locate for a governed document without either; (4) the whole document. Roster-anchored extraction chooses its own windows. Whichever scope wins, the final input must still fit max_context; a manual scope controls which pages are read, never whether the budget applies.

Targeting normally runs within each bounded extraction worker, so a slow locator doesn’t hold up every other document. A fresh run with existing output performs bounded targeting preflight before deleting old records. Its model is required when auto_locate is enabled and must resolve to a different provider/model than extraction.model; it is never inherited. Target-scoped selections retain subject identity/header context. By default the subject comes from the last configured partition_by field (the roster’s name field), not from parsing a display label or guessing metadata fields. A source may name the target differently (a county minute never repeats a directory label such as Company: Site, ST), so subject_fields optionally lists target columns whose values are used as identity phrases, e.g. [utility_name, short_name]. Field names are exact column names, not fuzzy aliases. Phrases are alternate names for the configured target, not evidence; they are not required to be unique, and broad terms (an organization, place or category) are weaker hints. Matching stays whole-phrase after the same normalization as the roster. Phrases apply only to target-scoped documents that automatic targeting governs; shared-source hints, shared-roster candidate scans, manual page overrides and off-roster behaviour are unchanged. The key is opt-in and validated at config resolution (run/extract --validate-config included): it must be a non-empty list of unique names, discovery.targets must be set, every name must be a target column (urls and query are inputs, not columns), and column values must be scalars (null/blank are skipped; numbers and booleans use their string form; lists/objects are rejected). Values come from the current target rows, joined to each document by its stable target id, not from the metadata saved at discovery, so a corrected or newly added phrase takes effect without rediscovery. A target id missing from the current targets gets no phrases (a warning is logged). Absent, behaviour and caches are unchanged. Setting or changing the field list changes the extraction fingerprint, so documents are extracted again once; afterwards, editing a phrase value re-extracts only the targets whose phrases changed. No regrade or rediscovery. Discovery labels and metadata remain untrusted scope hints, never factual evidence. Cache identities include the configured identity, subject hints and locator behavior version. HTML/HTM targeting uses readable section text against trigger_chars, not raw markup size, so scripts/styles and navigation do not turn a short article into a paid locator call.

Automatic targeting fails closed. A document it governs (enabled, a supported type, no CSV row, not handled by the roster bypasses) is extracted only from a bounded selection, or whole when its readable text is at most trigger_chars (or max_context when that is smaller, so a document that cannot fit is never left untargeted just because it is under trigger_chars). The exact final input must fit max_context (equal is allowed). Otherwise the document is held before any extraction request: a failed outcome with category targeting and code targeting_no_usable_scope (the locator failed, found nothing, or no page of the PDF could be read as text or OCR) or targeting_context_budget_exceeded. The prior record is left untouched, the extract stage ends failed (exit 1) even when other documents succeeded, so run stops before compiling; psweep compile can still be run by hand on the historical records. A CSV row, including a blank one that forces the full document, or pages.range bypasses targeting for every supported type but not the budget: an input over max_context is held with targeting_context_budget_exceeded (also when targeting is disabled or the type is unsupported), never truncated. A PDF that no parser or OCR could read at all needs such a row (and input_mode: auto or vision) to be extracted from page images. --fresh runs the same checks before deleting any output and, on a hold, keeps the previous records.

auto_locate shows the locator model the opening lines of each candidate page and asks for the pages of the described section. It then reads those pages in full and adds the parts they refer to elsewhere in the document, such as “charges specified in Tariff Sheet 75” or “riders on Sheet 80”, and repeats with the added pages until nothing new is referenced. max_selected_pages caps the total; the final selected pages are still read, so what they refer to is reported as omitted. Relevant pages it leaves out are logged as a warning and recorded in the record’s coverage.omitted_page_ranges. The extracted text marks each skipped stretch with [Omitted pages: 28-67]. Pages naming the target in a repeated header or footer count once toward the mandatory identity pages (the earliest occurrence is kept); pages naming it in the body all stay. A malformed page-range answer is rejected whole, not partly used. If the candidate index itself is too large for the locator’s route, it is split in halves and the answers are combined, so every candidate is still shown; more than 8 index requests for one document, or one candidate that cannot be sent alone, holds the document.

Selections are cached in .pages/ beside the document. If a reference pass fails, the pages found so far are extracted with coverage.targeting_incomplete and a warning in the record; such a record is never reused, and the document is located again on the next run. With save_discovered, extracted/discovered_page_ranges.csv (the pages.csv columns, one row per range) lists the pages behind every current record, reused records included. Non-PDF selections are saved under extracted/.sections/ as each document finishes; completed section text is then released from memory, whether saving is enabled or not.

LLM calls¶

Every transient provider failure — HTTP 408, 429 and 5xx, timeouts and dropped connections — is retried up to 4 attempts in total with exponential backoff (2 s, capped at 30 s). TLS failures and other 4xx errors are terminal. Each retry logs a warning with the model, the failure category and the attempt, prefixed with the document being processed; provider error text is never logged.

Request admission¶

Every request is measured as sent (messages, response schema, images) before a physical attempt, and nothing is sent or metered when it is refused. All callers are checked against model_context_windows. Extraction and locator requests are also checked against the pinned catalog and capped at the route’s output limit (see Units); discovery, reconciliation and audio transcription keep their own handling. A refusal is a failed document with request_not_admitted or context_window_exceeded and the prior record is left untouched. There is no fallback to another model.

Schema contract: provider strict mode versus local validation¶

The domain schema.json is the contract and is never rewritten to suit a provider. Strict provider json_schema mode is used only on a direct provider route (no endpoint override) whose model supports response schemas, and only when the original schema fits it (every object closed with all properties required, no unsupported keywords). Otherwise the request uses JSON-object mode with the schema in the prompt. A schema with optional properties, conditionals or composition therefore runs in JSON mode; that is expected, not a downgrade. In both modes the answer is validated locally with the format-aware validator, and the finalized payload is validated again before publication (see Final payload acceptance). Local validation is authoritative: a provider accepting an answer proves nothing.

Response outcomes and one schema-feedback generation¶

The model’s answer is classified before it is accepted. These outcomes are explicit failures (error category model_response) and are never regenerated, because a second paid call cannot repair them:

code

Meaning

response_truncated

The provider stopped at its output length limit; even schema-valid JSON is incomplete.

response_refused

The provider refused (a refusal field or content_filter termination).

An empty answer (response_empty), a non-JSON answer (response_not_json) or a JSON answer the schema rejects (schema_validation_failed) earns at most one feedback generation. It resends the original request unchanged (same schema, response format, selected evidence and output cap) plus the rejected answer and bounded diagnostics: failing path, rule, missing/unexpected key names, expected type, never document or answer values. A second invalid answer fails the document. A repaired record carries a schema_feedback validation note. Quote/evidence authenticity failures are never regenerated; they follow the existing verification path. A valid [] abstention is final.

Each document has one allowance of 4 physical provider attempts (the transient retry count above, not a new setting) shared by the original generation, the feedback generation, transport retries and the temperature fallback. A feedback generation runs only if an attempt remains; the failed answer’s cost stays in the failure’s usage. Roster candidate windows are separate extraction requests and each has its own allowance. Locator, discovery, reconciliation and audio-transcription requests keep their own existing semantics.

The prompt states that conversions or normalization happen only when a schema field description explicitly requires them, that unsupported conversions yield null, and that quotes stay verbatim.

Selected-page vision¶

extraction.input_mode is a PDF-only policy; other document types and the roster-anchored path stay text-only. Pages are rendered at full size (144 dpi PNG) from the captured source and sent after the text through the same request path, each preceded by [Image of PDF page N] with its original number. Only the pages in scope are rendered; nothing is cropped or dropped to fit.

  • auto attaches only unreadable pages (visual content that neither native text nor OCR could read). Clean documents stay text-only and cost the same. A document with no readable text at all proceeds on images instead of failing, once its scope is set (see Page selection).

  • Re-run cost. A record with unreadable pages is parser_partial and is never reused, even when images covered those pages. A domain that sets auto or vision therefore pays again, including image input, on every re-run of a document with unreadable pages. There is no switch to accept such a record as final.

  • vision attaches every non-blank selected page, alongside its text. Use page targeting or ranges; an unscoped long PDF is held by a known context window.

  • The route must be known to accept images (LiteLLM’s pinned catalog, checked on the model name and the resolved model). An unmapped proxy alias holds with request_not_admitted before any request; there is no fallback to another model. Image size is estimated from each PNG’s own dimensions (pixels / 750 + 256 per image, high on purpose) and counted against known input windows.

  • Quotes are still verified against text only. Content that exists only in an image has no text to match, so a quote taken from it is rejected like any other unverifiable quote. The record’s input block states the mode, the per-page representation, visual_pages and render_dpi; coverage image_only_pages lists sent pages that had no readable text, with a matching warning that their values rest on page images alone. A page that has text (vision mode) is not image-only.

  • Native PDF transport is not implemented.

  • A non-text mode joins the extraction fingerprint (mode and dpi), so switching modes re-extracts. text adds nothing to it.

Record input provenance¶

Every record has an input block (record contract 3.0.0), outside the domain payload and bounded to metadata (no rendered bytes): input_mode (the mode in effect; the roster path and non-PDF documents are text), pages (each selected PDF page with status, chars, image_fraction and, when OCR output was obtained for it, ocr_sha256), visual_pages and render_dpi (only when images were sent). Coverage gains unreadable_pages (the selected pages no parser could read) and image_only_pages; the parser_partial warning names the unreadable pages (PDF pages 4,7 could not be read as text or OCR). Coverage has no context_truncated key: an oversized input is held, never truncated. Records declare contract_version 3.0.0; records of any other version are not read and are re-extracted.

Reuse proof for OCR. A record is reusable only while every valid OCR page entry in the cache agrees with the ocr_sha256 the record used for that page. A missing entry is unknown and regenerable, so it keeps reuse (no provider call); a present entry that differs, or one for a page the record could not read, makes the record stale; entries for pages outside the record’s selection are ignored. Transcripts carry a derived_text_sha256 proof in the run manifest instead. The check repeats at consumption.

Source identity¶

Each extracted record describes the exact bytes that were read. Extraction snapshots the source into a private temporary directory while hashing the same bytes, requires that digest to equal the one fingerprinted during preparation, and uses the snapshot for every read, quote check, and the record’s document.source_sha256. If the file changed after preparation the document fails with source_changed before any paid request and nothing is published; rerun extraction. The original path remains the provenance path. Snapshots exist only for active consumers (including one-at-a-time roster scans and bounded fresh preflight workers), are owner-only, and are removed when the consumer finishes or is interrupted. Capture occurs before targeting: locator indexes, filtered sections, candidate windows, quote checks, and publication share the captured source and verified effective text. Original paths still key provenance and .pages/ / .sections/ sidecars.

Preparation retains compact method/text/representation identities. Missing or changed authoritative browser/API text cannot fall back to native text under its old fingerprint. Transcripts must match the source and transcriber identity. Raw OCR is derived from the source per page (see Caches); each record stores the digest of the OCR text it used per page (see Record input provenance). Derived OCR/transcript caches can be created without perpetual re-extraction; changed verified derived text rejects reuse. Roster/no-match decisions and reused records are rechecked at consumption. Fresh preflight releases captures promptly and rechecks retained scope identities inside workers. Prior records survive a mismatch; stale-product cleanup occurs only after every fresh document succeeds (successful siblings may still publish). An empty fresh inventory leaves prior outputs intact. Saved page scopes exclude failed reuse as well as failed new extraction. Cached-only audio uses the same transcript acceptance rule as configured transcription; newly appearing derived text must match the selected record’s consumption proof before reporting reuse. Manifest record digests come from the exact bytes atomically published by the writer (which returns item count plus SHA-256), never a later live-output hash.

Final payload acceptance¶

The domain schema is the contract for what is published, not only for what the model returned. After every mutation (normalization, roster filtering, quote and evidence verification) the record writer validates the finalized payload against the resolved schema, then the record envelope, then publishes atomically. If quote filtering removes the only row of a minItems: 1 array, or evidence nulling breaks a composite constraint, the document fails with schema_contract and any previous record is left untouched. Unsupported claims are never reinstated or invented to satisfy the schema. Arrays that the schema allows to be empty still publish empty after filtering.

Current admission versus preserved history¶

Record bytes under extracted/ are history; compilation reads only what the output’s current admission admits. Every extraction invocation publishes run_manifests/current_admission.json atomically (not a *.manifest.json run manifest) with a disposition for each document in its scope, taken before limit: new or reused (admitted, with the exact record_sha256 published or verified), failed, or deferred (not admitted). A scoped run (single file, subtree) replaces only its own documents and keeps other entries while their record file exists. A failed or deferred document’s previous record is preserved on disk but not admitted, so a partial run compiles its succeeded and verified-reused siblings and never a stale sibling. Terminal targeting holds stay failures. Admission is never inherited from an earlier globally successful run.

Extraction holds a single-writer lock per output (.<output>.publication.lock, beside the output directory); a second concurrent extraction into the same output is rejected. Reuse decided at preparation is re-verified against the record’s proof digest once the lock is held; a record replaced in between fails that document (rerun extraction).

Each admitted pointer entry carries the record digest plus the consumed source_sha256 and input_fingerprint. A run marks the documents it will rewrite deferred before writing, so an interrupted run leaves them excluded from compilation until psweep extract is rerun.

psweep compile (and compile_extractions) select admitted records through one selector shared by provenance checks, row/roster/reconciliation compilation, dry-run, and the build fingerprint, and read exactly the bytes whose digest admission recorded. Fail-closed cases: unreadable/malformed pointer, an admitted record that is missing or whose bytes changed, and an extraction directory with run manifests but no admission (rerun psweep extract). Excluded preserved records are reported as a count, not a warning, so provenance_policy cannot readmit them. A standalone directory with no run evidence compiles as historical_unverified (recorded in the compile manifest as outputs.admission.qualification; current otherwise). The build fingerprint includes the qualification and admitted digests, so a change in admission makes a compiled table stale even when record bytes are unchanged.

When every admitted record is a valid empty result and nothing failed, an empty table is a successful result. If failed documents exist and the compiled table has no rows, compile status is failed (nonzero exit) instead of a clean success; the table is still written. The extraction manifest status adds items and zero_item_records. Admission never calls a model.

Roster-anchored extraction¶

When the schema’s identity.deduplication.key_fields equal discovery.partition_by, extraction runs in roster mode: entity names in the text are matched exactly (after normalization) against the roster’s last partition_by field. A name shared by targets in different states is assigned by state evidence near the match, falling back to the whole document: addresses (, AZ or AZ 85001), full state names, state-labelled table cells (State: CA), or a state code alone on the line after a line that is exactly a roster name. Without evidence every candidate is kept. Names unique to one target are never dropped. Partial overlap between key_fields and partition_by is an error.

Audio¶

Recordings (.mp3 .m4a .wav .ogg .flac) are documents. Set extraction.transcription_model to a models: alias of a transcription model. ffmpeg (installed by pixi) transcodes each recording to mono 16 kHz MP3 and splits it into ~5-minute chunks cut at the quietest point; chunks are transcribed in parallel and each starts with an exact [hh:mm:ss] offset. Measured cost is about $0.22 per audio hour. Transcripts are cached beside the recording in .text/<filename>.txt (with .meta.json), like OCR text, so each file is transcribed once.

Roster mode. When discovery declares targets and partition_by, compile emits one row per target in roster order. A list of primitives becomes one comma-joined cell; other lists and objects become compact JSON. Extra target columns pass through, plus sources, confidence and evidence ({field: {value, url, support}}, adding the quote of each evidence field and conflict: true when sources disagree). support is the number of distinct, nonblank recorded source URLs among the observations the resolver retained that agree with the chosen value. It is a URL-coverage count, not a truth, independence or authority score: several URLs can copy one claim, and local or manual evidence without a URL can populate a valid cell with support: 0. Compare counts only within the same resolver and group settings, and look at the sources.

confidence is a row-level flag, not a quality score, and it is not derived from support. Without reconciliation it is the lowest level over the populated cells: high when two or more recorded sources agree, medium for one, low when a cell’s sources conflicted; a row with no populated cell is none. With reconciliation it is low whenever the target needed arbitration or schema reconciliation (including abstained or unresolved units, even if another populated cell has several supporting URLs), otherwise high or medium from the weakest unit’s source agreement. Manual or blank-URL sources still count toward this existing bookkeeping, which is why it can differ from support.

Excel batches above 1,048,575 rows or with cells over 32,767 characters fail before export; use CSV for large outputs.

Scored subset (default: every scorable field).

min_accuracy

Gate in (0, 1]: exit 1 when the primary falls below it against any reference. Needs references.

key_fields, quote_field

Rows mode (no roster) only: row identity (required there) and each row’s verbatim quote.

Precision, coverage and reference labels¶

Validation reports populated-answer precision (correct_populated / assessed_populated), answer coverage (populated_answers / answer_opportunities) and reference-supported recall alongside existing assessed-cell accuracy. Unknown labels do not reward abstentions. In reference CSVs:

  • A populated cell is assessed by default; explicit NA labels known absence.

  • An empty cell is unlabelled, unless optional <compiled title>__assessed=true explicitly labels absence.

  • <compiled title>__assessed=false excludes any value as unknown/unassessed; no domain-specific magic unknown word is reserved. Nonblank masks must be true or false.

min_accuracy remains an assessed all-cell accuracy gate, not populated-answer precision. Model agreement is labelled separately and is not ground truth. Counts include missing/no-answer targets and expose unassessed populated claims, reference contradictions and evidence conflicts. Exact-target source precision still needs a separate sampled source audit; reviewer labels alone cannot certify it.

Per-field Wilson intervals are provided in roster mode (one cell per target). Pooled cell intervals are null because fields/rows from one target are correlated. Target-level summaries provide answer/no-answer/partially assessed counts and an all-answered correctness interval over fully assessed answered targets. Those denominators must be read with coverage; blanks cannot establish an 85% precision claim. Processing time and billed extraction cost per target are amortized record-only means, not complete discovery spend or target wall time.

For a defensible rollout, freeze a representative random/stratified holdout without manually seeded references, separate it from tuning cases, and label source-supported answers. Report status/milestone results and coverage separately, with denominators and uncertainty. Architecture or provider/model choice is not proof of greater-than-85% performance.

At least one of models or references is required. Cells where every contender agrees are not judged; the judge sees only disagreements, checking each candidate against its quote. Misses are labelled no_docs (no curated document) or extraction. Accuracy carries a 95% Wilson interval. validate --sample N [--seed S] writes a blank, seeded labelling sheet with no LLM calls. Outputs in outputs/<domain>/validated/: cells.csv, summary.csv, summary.json.

Supported inputs (discovery downloads exactly these; extraction reads them):

Kind

URL eligibility (always on): a URL with a supported extension, no extension, or a suffix unknown to Python’s MIME table (.php, .aspx, .cfm, …) is eligible — the response MIME type decides what it is. A suffix of a known unsupported type or encoding (.jpg, .zip, .gz) is rejected before download.

Byte limits. Files streamed to disk stop at 1 GiB decoded (PSWEEP_MAX_RESPONSE_BYTES overrides it) and abort after runtime.timeout_seconds without data. Pages, search and API responses read into memory stop at 50 MiB and must finish within the timeout. An oversized response is a failed download (partial_failure), never retried; raise the limit and rediscover with --fresh.

Runs, reuse and exit codes¶

run stops at 1 or 2, continues past 3, and exits 3 at the end when any stage was partial. Exit codes do not depend on -q/-v.

Before anything runs, the run plan lists the paid stages: the upper bound on SerpApi queries (before the cache) with its ceiling, the review, extraction, page-targeting and reconciliation models, and any model without a catalog price (Price unknown: its spend is not metered in dollars). --yes and -q skip the prompt. After a partial discovery, run warns before extraction starts (extraction uses the current curated set, which keeps earlier documents for incomplete targets) and then continues; re-run psweep discover first to retry the incomplete targets without paying for extraction.

Discovery resume. The checkpoint (discovered/checkpoint.json) records each target and shared source separately, keyed by the effective config fingerprint and SHA-256 evidence of its files. Adding a target fetches only that target; changing a target’s urls or rendered queries re-runs it.

  • A complete item makes no requests on the next run. Fully reused runs write an audit snapshot, not another documents/ or curated/ copy.

  • Extraction/page-locator model changes do not invalidate discovery. Only the resolved model used by configured document_review affects its fingerprint.

  • When acquisition settings or a target’s inputs change, discovery re-evaluates that work but reuses matching URL/owner downloads from verified local bytes; it fetches only new, missing or changed documents. Classification and review are re-applied under the current settings. Use --fresh to fetch remote changes at already-downloaded URLs, including changed redirect destinations.

  • An item left incomplete — transient failure, unfinished crawl or search, max_pages or max_files reached — publishes what it has additively, and the next run re-fetches the listing, reuses every earlier download whose SHA-256 still matches (no request, no max_files slot), skips terminal outcomes (e.g. 404) and fetches only the rest. A capped listing converges batch by batch. An incomplete partition never removes a document the run did not decide, but every final per-document decision still applies to the consolidated curated/ and download_index.csv: a human reject (psweep curate), a final non-selection (review keep_top, max_per_target, a rejected grade) and a document republished under a new name. Only “this completed target no longer lists the document” waits for the partition to complete. Extraction records of a removed document become historical; nothing under extracted/ is deleted by discovery.

  • Transient failures (timeouts, connection errors, truncated streams, HTTP 408/429/5xx) are retried in the run and leave the item incomplete. Bot challenges (429/5xx with cf-mitigated, x-vercel-mitigated or x-amzn-waf-action) are retried in the run but are final across runs. TLS errors and other 4xx responses are terminal.

  • discover --fresh ignores the checkpoint and search cache, re-checks completed listings (new children of a completed listing need it), and replaces the curated partitions of the targets it processes.

Extraction reuse. Reuse is always on; extract --fresh re-extracts every document. A record is reused only when source, schema, resolved model and settings, and record bytes still match; otherwise it is re-extracted. The settings are the consumed source and effective-text digests, the locator configuration and behaviour version, a non-text input_mode with its render dpi, the extraction behaviour version (prompt and one-feedback-generation policy) and, for PDFs only, the OCR and page-representation versions. Changing a PDF-only version never re-extracts other formats, and input_mode: text adds nothing to the fingerprint. extraction.timeout_seconds and pages.auto_locate.save_discovered are part of the reuse fingerprint: adding, changing or removing either re-extracts every document of the domain (paid). Settle them before a large run. parser_partial and targeting_incomplete records are re-paid on every run (see Re-run cost under Selected-page vision). A record is also never reused when it is parser_partial, has targeting_incomplete under automatic targeting, has a different contract_version, or disagrees with a present OCR page entry (see Record input provenance). Reuse needs no credentials. A record whose source document no longer exists under the input folder is withdrawn: extract deletes it, names it in the summary and lists it under withdrawn in the run manifest, so compile drops its rows. Records from other input folders are left alone, and validate reports a primary with records to withdraw as stale. extract --fresh resets the output after a successful preflight. compile --fresh clears stale compiled files; validate --fresh clears validated/. run --fresh passes --fresh to every stage.

PDF page representation. Each selected page is judged on its own, never by a document total. A page with a text layer is native. A page mostly covered by raster images (at least half its area) with under 500 characters of text, or with no text and visible images or drawings, is OCR-ed locally and marked ocr. A page with nothing to read is blank (OCR is never attempted and it counts as covered); decorative images such as logos do not change that. A raster page that OCR cannot read (or when OCR is unavailable) is unreadable. Only native, ocr and blank pages count as extracted_pages, so an unreadable selected page makes the record’s coverage parser_partial with a warning instead of being certified as extracted. The per-page status is in the extraction metadata under pages and keeps the original page numbers; the page locator’s index OCRs raster pages too, so scans can be targeted. ocr_corrections apply only to OCR pages, each time the text is read. pdf_inspection and discovery screening read native text only.

Caches. Raw OCR: one entry per page in .text/<filename>.ocr/<page>.json, keyed by the source SHA-256, the page number and the OCR engine/render version, and shared by the page locator’s index, page-range runs and whole-document extraction, so a raster page is OCR-ed once. Entries hold raw text only (the configured corrections are applied on read) and are replaced atomically; an unreadable, mismatched or tampered entry is a miss and is rewritten. The entry key includes the PyMuPDF version but not the Tesseract version, so upgrading Tesseract keeps existing OCR text until the .ocr directories are deleted. Discovery moves entries with their document (into curated/, to a same-SHA re-download, and out on removal). Transcripts and browser/API renders: .text/<filename>.txt + .meta.json beside the document, verified by size, mtime and SHA-256 and carried to a re-downloaded file with the same SHA-256. Page/section targeting: .pages/, .sections/. Review grades: discovered/.review_cache/. Delete a cache directory to force that work again.

Offline verification¶

Testing is controlled by pytest/Pixi, not by domain run.yaml settings. pixi run --locked -e dev test remains the complete offline CI gate, including real local TLS, subprocess CLI, ffmpeg, and large-scale regressions. pixi run --locked -e dev test-fast is an optional development loop excluding explicit integration, slow, and live markers; unmarked tests still run. Unknown markers fail collection. Neither command enables external endpoints or changes extraction/review caches. See Contributing for focused commands and the explicitly opt-in live layer.
