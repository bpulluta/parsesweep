Command Reference¶

Every command is generated directly from the CLI itself, so the options and their defaults shown here always match runtime behavior.

psweep¶

📄 [bold]ParseSweep[/bold] — AI-powered structured data extraction from documents.

[dim]Run [cyan]psweep[/cyan] with no arguments for an interactive guided menu.[/dim]

Usage

psweep [OPTIONS] COMMAND [ARGS]...

Options

-V, --version¶

Show version and exit.

Default:

False

--install-completion¶

Install completion for the current shell.

--show-completion¶

Show completion for the current shell, to copy it or customize the installation.

benchmark¶

Build a performance profile from run manifests and evaluate benchmark gates.

Usage

psweep benchmark [OPTIONS] [PATH]

Options

--gate-profile <gate_profile>¶

JSON file containing benchmark input paths and gate thresholds for reproducible release evaluation.

--extraction-baseline-dir <extraction_baseline_dir>¶

Directory containing expected extraction JSON records for parity scoring. Files should mirror benchmark output relative paths or record filenames.

--validation-baseline-dir <validation_baseline_dir>¶

Directory containing expected QA/QC comparison_report.csv files for signal-quality scoring. Files should mirror benchmark document-folder relative paths.

--compilation-baseline-dir <compilation_baseline_dir>¶

Directory containing expected compiled CSV outputs for row-correctness scoring. Files should mirror benchmark CSV relative paths or filenames.

--compilation-schema <compilation_schema>¶

Schema used to generate compiled outputs. Required for compilation correctness scoring.

--baseline-snapshot <baseline_snapshot>¶

Path to a saved benchmark snapshot used for median throughput/cost delta comparison.

--write-snapshot <write_snapshot>¶

Write the current benchmark metrics to a snapshot JSON file.

--snapshot-label <snapshot_label>¶

Optional label to store in a written benchmark snapshot.

--min-extraction-parity <min_extraction_parity>¶

Minimum required extraction parity percentage (0-100) when expected extraction records are provided.

--min-validation-signal-quality <min_validation_signal_quality>¶

Minimum required QA/QC signal quality percentage (0-100) when expected comparison reports are provided.

--min-validation-qualitative-pass-rate <min_validation_qualitative_pass_rate>¶

Minimum required percentage (0-100) of qualitative QA/QC comparison summaries whose advisory gate status is pass.

--min-compilation-correctness <min_compilation_correctness>¶

Minimum required compilation correctness percentage (0-100) when expected compiled CSVs are provided.

--max-failure-rate <max_failure_rate>¶

Maximum allowed failed-document rate (0-1).

--max-average-seconds-per-document <max_average_seconds_per_document>¶

Maximum allowed average processing seconds per document.

--min-documents-per-minute <min_documents_per_minute>¶

Minimum required successful document throughput.

--max-total-errors <max_total_errors>¶

Maximum allowed total structured errors across manifests.

--max-throughput-delta-percent <max_throughput_delta_percent>¶

Maximum allowed median time-per-document increase versus the baseline snapshot.

--max-cost-delta-percent <max_cost_delta_percent>¶

Maximum allowed median cost-per-document increase versus the baseline snapshot.

-q, --quiet¶

Minimal output (machine-readable)

-v, --verbose¶

Detailed output

Optional argument

compile¶

Compile extracted JSON files into clean Excel/CSV output.

Reads per-document JSON files from EXTRACTED_DIR (or the configured input_dir), deduplicates records using the schema’s identity rules, and writes a consolidated Excel and/or CSV file to the output directory.

Use –fresh to clear the compiled output directory (stale CSV/XLSX) before writing new results. Pair with ‘extract –fresh’ for a guaranteed clean pipeline run.

Run psweep compile --help for every option and its default.

Examples¶

psweep compile --config config/my_domain/run.yaml
psweep compile extracted/my_domain/ --schema schemas/my_schema.json
psweep compile extracted/ --schema s.json --dry-run --verbose

Usage

psweep compile [OPTIONS] [EXTRACTED_DIR]

Options

--config <config_path>¶

Domain run config file (RECOMMENDED — compile input, schema, and output paths)

--show-effective-config¶

Print resolved command inputs with source attribution and continue

--validate-config¶

Validate resolved command inputs and exit without compiling

--config-strict¶

Fail on unknown keys in runtime config sections

-s, --schema <schema>¶

Schema file (for quick testing without a config YAML)

-o, --output <output>¶

Output directory (auto-detected if not specified)

--dry-run¶

Preview compilation and deduplication without writing output files

--report-format <report_format>¶

Dry-run preview output format

Default:

'text'

Options:

text | json

--fail-on-suspicious <fail_on_suspicious>¶

With –dry-run, exit non-zero when suspicious duplicate groups meet this severity threshold

Default:

'none'

Options:

none | high | medium | low

--provenance-policy <provenance_policy>¶

How to handle compile input provenance warnings (missing schema_id, unresolved artifact_id, mixed lineage/orphan records).

Default:

'warn'

Options:

warn | fail

--fresh¶

Clear the compiled output directory (stale CSV/XLSX) before writing new results. Pair with ‘extract –fresh’ for a guaranteed clean pipeline.

-q, --quiet¶

Minimal output (machine-readable)

-v, --verbose¶

Detailed output with statistics

discover¶

Discover and download source documents from web targets.

Searches for documents matching the configured queries, scores and filters candidates, then downloads accepted files to the discovery output directory. Supports seeding from a CSV of targets, direct seed URLs, or a SerpApi search query. Resumes from a checkpoint on subsequent runs; pass –fresh to re-run all targets from scratch.

Run psweep discover --help for every option and its resolved default.

Examples¶

psweep discover --config config/my_domain/run.yaml
psweep discover --seed-url https://example.com/docs --domain my_domain
psweep discover --config config/my_domain/run.yaml --dry-run --verbose

Usage

psweep discover [OPTIONS] [TARGET]

Options

--config <config_path>¶

Domain run config file (RECOMMENDED — discovery targets, providers, and output paths)

--show-effective-config¶

Print resolved command inputs with source attribution and continue

--validate-config¶

Validate resolved command inputs and exit without running discovery

--config-strict¶

Fail on unknown keys in runtime config sections

--domain <domain>¶

Domain key for discovery output structure

--seed-url <seed_urls>¶

Seed URL for discovery (repeatable)

--query <query>¶

Discovery query hint for seeker stage

--state <state>¶

Optional state hint used for jurisdiction-based output organization (for example: CA, Colorado)

--jurisdiction <jurisdiction>¶

Optional jurisdiction hint used for output organization (for example: Imperial County)

--partition-mode <partition_mode>¶

Download organization mode: auto prefers jurisdiction when available, else host

Default:

'auto'

Options:

auto | jurisdiction | host

-n, --target-limit <target_limit>¶

Limit discovery to the first N configured targets after config resolution.

--retention-documents <retention_documents>¶

Retention mode for downloaded documents: all, curated, or none.

Options:

all | curated | none

--digger-provider <digger_provider>¶

Digger provider (for example: seed_only, http, crawlee_playwright)

--enable-serpapi, --disable-serpapi¶

Enable optional SerpApi seeker provider

--max-concurrent-downloads <max_concurrent_downloads>¶

Maximum parallel downloads during discover runs

--min-request-interval-ms <min_request_interval_ms>¶

Minimum delay between outbound discovery requests in milliseconds

--robots-policy-mode <robots_policy_mode>¶

Robots policy mode for target-site requests

Default:

'warn'

Options:

ignore | warn | enforce

--tos-policy-mode <tos_policy_mode>¶

Terms acknowledgement mode for target-site requests

Default:

'warn'

Options:

ignore | warn | enforce

--acknowledge-tos-domain <acknowledged_tos_domains>¶

Host or parent domain acknowledged for target-site terms checks (repeatable)

--output-documents <output_documents>¶

Directory for discovered documents (defaults to run-scoped deterministic path)

--output-manifest <output_manifest>¶

Path to discovery manifest JSON (defaults to run-scoped deterministic path)

--dry-run¶

Discover and emit manifest scaffold without downloads

--fresh¶

Re-run all targets from scratch: clears the checkpoint, bypasses the search-result cache, and replaces the curated/ partitions for every jurisdiction processed this run. Jurisdictions not touched by this run keep their existing curated files.

Default:

False

-q, --quiet¶

Minimal output

-v, --verbose¶

Detailed output

--debug¶

Debug output with diagnostic context

extract¶

Extract structured data from documents using an LLM.

Reads PDF, DOCX, TXT, and XLSX files from PATH (or the configured input_dir) and writes one JSON file per document to the output directory. Already-processed files are skipped by default; pass –fresh to re-extract documents that already have output JSON (cached text/sidecars are still reused). Output defaults to extracted/<domain>/ when –output is omitted; run psweep extract --help for every option and its default.

Examples¶

psweep extract --config config/my_domain/run.yaml --fresh
psweep extract docs/ --schema schemas/my_schema.json
psweep extract docs/ --schema s.json --model gpt-4o --provider azure

Usage

psweep extract [OPTIONS] [PATH]

Options

--config <config_path>¶

Domain run config file (RECOMMENDED — extraction input, schema, model, and output paths)

--show-effective-config¶

Print resolved command inputs with source attribution and continue

--validate-config¶

Validate resolved command inputs and exit without extracting

--config-strict¶

Fail on unknown keys in runtime config sections

-o, --output <output>¶

Output directory (auto-detected if not specified)

-s, --schema <schema>¶

Schema file (for quick testing without a config YAML)

--category <category>¶

Category name (auto-detected from path if not specified)

--model <model>¶

LLM model name, or an alias defined in the run.yaml models: block. For Azure, use your deployment name (e.g. gpt-4o).

Default:

'gpt-4o-mini'

--provider <provider>¶

LLM provider (auto-detects from .env)

Default:

'auto'

Options:

openai | azure | anthropic | gemini | auto

--profile <profile_name>¶

Runtime profile to compile into artifact lineage (for example: default, dev, staging, prod)

Default:

'default'

-n, --limit <limit>¶

Process only first N files

--fresh¶

Re-extract documents that already have output JSON, overwriting it. Cached document text (.text_cache) and page-targeting sidecars (.pages) are reused. Pair with ‘compile –fresh’ to also clear compiled outputs.

Default:

False

--max-context <max_context>¶

Max document characters to process

Default:

600000

-q, --quiet¶

Minimal output (machine-readable)

-v, --verbose¶

Detailed output with statistics

--debug¶

Debug mode with full logs

--live-dashboard¶

Show live dashboard during extraction

--pages <pages>¶

Page range to extract (e.g., “615-759”). Only for single PDF files.

--pages-csv <pages_csv>¶

CSV file mapping documents to page ranges

--from-index <from_index>¶

Load discovered files from a download_index.csv (bypasses PATH argument)

--filter <index_filters>¶

With –from-index: keep only rows where COLUMN matches VALUE (format: column=value; repeatable; matches any download_index.csv column)

Arguments

PATH¶

Optional argument

init-domain-schema¶

Create a lean starter schema for a new domain.

This command is the documents-first entry point for greenfield onboarding. It derives a compact starter schema from the closest existing reference schema, preserving only the minimal extraction contract and core row shape needed for the first smoke extraction pass.

Usage

psweep init-domain-schema [OPTIONS]

Options

--interactive¶

Prompt for missing starter-schema values

--name <schema_name>¶

Base schema name (used for the output file)

--reference-schema <reference_schema>¶

Existing schema file used as the closest reference for a lean starter

--domain <domain_name>¶

Override the metadata domain label

--document-type <document_type>¶

Override the human-readable document type

--include-field <include_fields>¶

Limit the starter schema to these main-array item fields; repeat the option to keep multiple fields

--output <output>¶

Output schema path (defaults to schemas/personal/<name>_schema.json)

--force¶

Overwrite an existing schema file if it already exists

--report-format <report_format>¶

Output format for scaffold results

'text'

text | json

run¶

Run the full pipeline: discover → extract → validate (optional) → compile.

Shows what will be reused from previous runs and what is new, then asks for confirmation before proceeding. Use [cyan]–fresh[/cyan] to ignore all previous work and start fresh.

[bold]Usage:[/bold]

psweep run –config config/my_domain/run.yaml psweep run –config config/my_domain/run.yaml –target-limit 3 –fresh –yes

[bold]Adding new targets:[/bold]

  1. Add rows to config/<domain>/targets.csv

  2. Run: psweep run –config config/<domain>/run.yaml

  3. Only new targets are processed; previous results are preserved.

Usage

psweep run [OPTIONS]

Options

--config <config_path>¶

Required Path to the domain run config file (e.g. config/<domain>/run.yaml).

--fresh¶

Ignore all previous work and start fresh — re-run every discovery target (ignoring the checkpoint and search cache), clear extracted and compiled outputs, then re-extract every document from the newly discovered curated set before recompiling.

Default:

False

-n, --target-limit <target_limit>¶

Limit discovery to the first N configured targets for this run.

--retention-documents <retention_documents>¶

Discovery document retention mode: all, curated, or none.

--skip-discover¶

Skip discovery (use existing curated docs).

Default:

False

--skip-extract¶

Skip extraction (compile from existing JSON).

Default:

False

--validate-config¶

Validate resolved run-stage config and exit without executing stages.

Default:

False

--config-strict, --no-config-strict¶

Fail on unknown keys in runtime config sections during run preflight.

Default:

True

-y, --yes¶

Skip confirmation prompt.

Default:

False

-q, --quiet¶

Minimal output.

Default:

False

-v, --verbose¶

Detailed output.

Default:

False
